Open source · self-hosted · MIT

Your documentation lives in Git, not in a database.

DocuWaves is a documentation site you run yourself. Every project, category and page is a Markdown file in a Git repository you own, and every save in the browser editor is a commit. History, diffs, attribution and restore are simply the repository being there.

$ curl -fsSL https://get.docuwaves.app | sudo sh

Sets up DocuWaves behind Caddy with a Let's Encrypt certificate, nightly backups and the docuwaves command. Debian, Ubuntu, Rocky and Alma, on amd64 and arm64. Read the script first or use Docker Compose.

Why DocuWaves

A docs site that keeps nothing to itself

Your content is files in Git, readable without the app. The app is a fast way to write, review and publish them.

Every save is a commit

There is no revisions table. A page's history is its file's Git history: author, date, a coloured diff and a restore that adds a new commit on top.

Assistants with receipts

An MCP endpoint lets an AI assistant read and, with the right token, write your docs. Every write is a commit authored by that token, one git revert from undone.

A format you can leave with

Markdown with a short YAML header, in a layout that is written down as an open specification, with a test suite and an independent checker.

Writing

Write visually or in Markdown. The file stays Markdown.

A visual editor with a slash menu and a format bar, or Markdown side by side with a live preview. Switching loses nothing.

  • Blocks that still read on GitHubCallouts, tabs, steps, Mermaid diagrams, snippets and {{variables}}, all as plain text.
  • Images by paste or dragUploaded to the project's assets/, committed, and referenced at the cursor.
  • Unsaved work survivesText is kept in the browser and offered back when you return, never applied silently.
Content in Git

The answer the app gives is the answer git log gives

DocuWaves does not keep a copy of your content. The database is a search and browse index you can delete; it is rebuilt from the repository on the next start.

  • History, diffs and restoreEach page has a History tab with the real commits that touched its file.
  • Pull requests just workSomeone can fork the content repository, edit a .md file and open a pull request. The merged change is picked up on its own.
  • No Git host requiredOn first start DocuWaves runs git init in its own volume. Add a remote later and the full history is pushed to it.
AI assistants

Hand an assistant write access, and keep the receipts

Point an assistant at /api/mcp with a bearer token. It can browse, search and read your docs, and write them if the token says so.

  • No delete tool, on purposeCreating and rewriting are recoverable. Deleting stays in the admin, where a person confirms it.
  • The token opens one doorRead and write are separate scopes, tokens can expire, and a token cannot reach the rest of the admin API.
  • Nothing added to an AI billThe endpoint is a tool server. It never calls a language model itself.
# every assistant write, and how to undo one
git log --author='API token'
git log --author='notes-bot'
git revert <sha>
Working together

More than one person, without a permissions maze

Each rule is small and plain rather than a matrix to configure.

Four roles

Reader, Read, Write and Manage. Password or OIDC single sign-on, with passkeys, security keys or an authenticator app.

Approval before publishing

One line in a project's settings and nothing goes live until a second person approves, with comments on the passage.

Preview links for drafts

Show one unpublished page to someone without an account, through a link that expires.

Private projects

Projects only signed-in readers can open, next to public ones in the same instance.

Who else is editing

The editor shows who has the page open, and a save that would overwrite a newer one is stopped and shown.

Webhooks

Announce published pages and pending approvals in Discord, Slack, Teams, Matrix or at any URL.

Your look

Two deployments look like two different products

Name, logo, colours, fonts and footer come from a _site.yml in the content repository, versioned and reviewable like a page.

  • Ready-made themesPick one with a click, then adjust tone, corner radius and header style with a live preview.
  • Light and dark, checkedContrast is checked in both, and an automated accessibility test runs on every change.
  • Custom CSS when you need itFor the last few pixels a theme does not cover.
Open by design

MIT, no paid tier, and a content format anyone can implement

Everything on this page is in one open-source repository. Nothing sits behind a subscription, and your content is not tied to DocuWaves either.

A written specification

Every file and field DocuWaves reads and writes is described in the content format, version 1.0.

A conformance suite

Example repositories with the result a correct reader must get. DocuWaves itself is tested against them.

A checker for your CI

docuwaves-lint checks a content repository without running DocuWaves. It needs Python and PyYAML, nothing else.

Bringing docs in

Start from what you already have

Moving to DocuWaves is an import, not a rewrite.

A ZIP of Markdown

MkDocs, GitBook, Docusaurus and Obsidian exports are recognised. A preview shows what will happen first; links are rewritten and images copied.

Confluence and Notion

A Confluence HTML space export or a Notion "Markdown & CSV" export becomes a project with its categories, pages and images.

Docs-as-code from CI

Keep a docs/ folder next to the code and let one CI step send it. A release tag freezes it as a version.

The everyday things

And the rest of it, briefly

  • Full-text searchAcross every published page, typo-tolerant, in the reader's language and version. What readers did not find is listed for you.
  • Ctrl+K quick searchWith bookmarks and recently read pages, kept in the reader's own browser.
  • PDF and printA whole project or one chapter as a manual with cover and contents.
  • Changelog and RSSA "What's new" page and feeds, built from the repository's history.
  • Several projectsOne instance serves the docs for every tool you maintain.
  • Multiple languagesOne page in several languages under one slug, with an honest notice where a translation is missing.
  • Frozen versionsFreeze the docs at a release; they stay readable while you keep editing.
  • Drafts and schedulingA page stays invisible until it is published, now or at a set time.
  • Ask the documentationOptional answers from your published pages only, with sources. Works with a local model.
  • Backups and diagnosticsA full export in one click, nightly backups, and a page that says what is configured.
  • Real HTML for crawlersTitles, descriptions, Open Graph, structured data, sitemap and robots.txt.
  • Works on phonesFor readers, and for writers in the admin and the editor.

Try it in about a minute

Docker with the Compose plugin is the only requirement. Every setting has a working default.

Docker Compose
git clone https://github.com/Syntaxlab-dev/DocuWaves.git
cd DocuWaves && cp .env.example .env
docker compose up -d --build
# then open http://<your-server>:8091

Prefer not to build? Use the image ghcr.io/syntaxlab-dev/docuwaves:stable.
