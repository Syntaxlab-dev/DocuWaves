Deine Dokumentation liegt in Git, nicht in einer Datenbank.

DocuWaves ist eine Dokumentationsseite, die du selbst betreibst. Jedes Projekt, jede Kategorie und jede Seite ist eine Markdown-Datei in einem Git-Repository, das dir gehört, und jedes Speichern im Browser-Editor ist ein Commit. Verlauf, Diffs, Autorenschaft und Wiederherstellen ergeben sich einfach daraus, dass das Repository da ist.

Warum DocuWaves

Eine Doku-Seite, die nichts für sich behält

Deine Inhalte sind Dateien in Git, lesbar auch ohne die App. Die App ist der schnelle Weg, sie zu schreiben, zu prüfen und zu veröffentlichen.

Jedes Speichern ist ein Commit

Es gibt keine Versionstabelle. Der Verlauf einer Seite ist der Git-Verlauf ihrer Datei: Autor, Datum, ein farbiger Diff und ein Wiederherstellen, das einen neuen Commit obendrauf setzt.

Assistenten mit Beleg

Über einen MCP-Endpunkt kann ein KI-Assistent deine Doku lesen und mit dem passenden Token auch schreiben. Jede Änderung ist ein Commit mit diesem Token als Autor, ein git revert macht sie rückgängig.

Ein Format, mit dem du gehen kannst

Markdown mit kurzem YAML-Kopf, in einem Aufbau, der als offene Spezifikation festgehalten ist, mit Testsuite und einem unabhängigen Prüfwerkzeug.

Schreiben

Visuell oder in Markdown schreiben. Die Datei bleibt Markdown.

Ein visueller Editor mit Slash-Menü und Formatleiste, oder Markdown neben einer Live-Vorschau. Beim Wechseln geht nichts verloren.

  • Blöcke, die auch auf GitHub lesbar bleibenHinweisboxen, Tabs, Schritte, Mermaid-Diagramme, Textbausteine und {{variables}}, alles als einfacher Text.
  • Bilder per Einfügen oder ZiehenHochgeladen nach assets/ im Projekt, committet und an der Cursorposition eingebunden.
  • Ungespeichertes bleibt erhaltenDer Text wird im Browser gehalten und beim nächsten Besuch angeboten, nie ungefragt übernommen.
Inhalte in Git

Die App sagt dasselbe wie git log

DocuWaves hält keine eigene Kopie deiner Inhalte. Die Datenbank ist nur ein Such- und Navigationsindex. Löschst du sie, wird sie beim nächsten Start aus dem Repository neu aufgebaut.

  • Verlauf, Diffs und WiederherstellenJede Seite hat einen Verlauf-Tab mit den echten Commits, die ihre Datei geändert haben.
  • Pull Requests funktionieren einfachJemand forkt das Inhalts-Repository, ändert eine .md-Datei und öffnet einen Pull Request. Die gemergte Änderung wird von selbst übernommen.
  • Kein Git-Hoster nötigBeim ersten Start führt DocuWaves git init im eigenen Volume aus. Trägst du später ein Remote ein, wird der ganze Verlauf dorthin gepusht.
KI-Assistenten

Gib einem Assistenten Schreibrechte und behalte die Belege

Richte einen Assistenten mit einem Bearer-Token auf /api/mcp. Er kann deine Doku durchsuchen und lesen und, wenn das Token es erlaubt, auch schreiben.

  • Bewusst kein LöschwerkzeugAnlegen und Umschreiben lassen sich rückgängig machen. Löschen bleibt im Admin, wo ein Mensch es bestätigt.
  • Das Token öffnet genau eine TürLesen und Schreiben sind getrennte Rechte, Tokens können ablaufen, und ein Token erreicht den Rest der Admin-API nicht.
  • Keine Zusatzkosten für KIDer Endpunkt ist ein Tool-Server. Er ruft selbst nie ein Sprachmodell auf.
# jede Änderung eines Assistenten, und wie man eine zurücknimmt
git log --author='API token'
git log --author='notes-bot'
git revert <sha>
Zusammenarbeit

Mehrere Leute, ohne Rechte-Labyrinth

Jede Regel ist klein und klar statt einer Matrix zum Konfigurieren.

Vier Rollen

Reader, Read, Write und Manage. Passwort oder OIDC-Single-Sign-on, mit Passkeys, Sicherheitsschlüsseln oder einer Authenticator-App.

Freigabe vor dem Veröffentlichen

Eine Zeile in den Projekteinstellungen, und nichts geht live, bevor eine zweite Person zustimmt, mit Kommentaren direkt an der Textstelle.

Vorschau-Links für Entwürfe

Zeige eine unveröffentlichte Seite jemandem ohne Konto, über einen Link, der abläuft.

Private Projekte

Projekte nur für angemeldete Leser, neben öffentlichen in derselben Instanz.

Wer noch bearbeitet

Der Editor zeigt, wer die Seite offen hat, und ein Speichern, das eine neuere Fassung überschreiben würde, wird gestoppt und angezeigt.

Webhooks

Melde veröffentlichte Seiten und offene Freigaben in Discord, Slack, Teams, Matrix oder an jede URL.

Dein Auftritt

Zwei Installationen sehen aus wie zwei verschiedene Produkte

Name, Logo, Farben, Schriften und Fußzeile kommen aus einer _site.yml im Inhalts-Repository, versioniert und prüfbar wie eine Seite.

  • Fertige ThemesMit einem Klick wählen, dann Farbton, Eckenradius und Kopfzeile mit Live-Vorschau anpassen.
  • Hell und dunkel, geprüftDer Kontrast ist in beiden geprüft, und bei jeder Änderung läuft ein automatischer Barrierefreiheitstest.
  • Eigenes CSS, wenn nötigFür die letzten Pixel, die ein Theme nicht abdeckt.
Offen von Grund auf

MIT, keine Bezahlversion, und ein Inhaltsformat, das jeder umsetzen kann

Alles auf dieser Seite steckt in einem Open-Source-Repository. Nichts liegt hinter einem Abo, und deine Inhalte sind auch nicht an DocuWaves gebunden.

Eine schriftliche Spezifikation

Jede Datei und jedes Feld, das DocuWaves liest und schreibt, ist im Inhaltsformat beschrieben, Version 1.0.

Eine Testsuite

Beispiel-Repositories mit dem Ergebnis, das ein korrekter Leser bekommen muss. DocuWaves selbst wird dagegen getestet.

Ein Prüfwerkzeug für deine CI

docuwaves-lint prüft ein Inhalts-Repository, ohne DocuWaves zu starten. Es braucht nur Python und PyYAML.

Doku mitbringen

Fang mit dem an, was du schon hast

Der Umzug zu DocuWaves ist ein Import, kein Neuschreiben.

Ein ZIP mit Markdown

Exporte aus MkDocs, GitBook, Docusaurus und Obsidian werden erkannt. Eine Vorschau zeigt vorher, was passiert. Links werden angepasst und Bilder übernommen.

Confluence und Notion

Ein HTML-Export eines Confluence-Bereichs oder ein „Markdown & CSV“-Export aus Notion wird zu einem Projekt mit Kategorien, Seiten und Bildern.

Docs-as-code aus der CI

Leg einen docs/-Ordner neben den Code und lass ihn von einem CI-Schritt schicken. Ein Release-Tag friert ihn als Version ein.

Der Alltag

Und der Rest, kurz gefasst

  • VolltextsucheÜber alle veröffentlichten Seiten, fehlertolerant, in Sprache und Version des Lesers. Was Leser nicht gefunden haben, wird dir aufgelistet.
  • Schnellsuche mit Strg+KMit Lesezeichen und zuletzt gelesenen Seiten, gespeichert im Browser des Lesers.
  • PDF und DruckEin ganzes Projekt oder ein Kapitel als Handbuch mit Deckblatt und Inhaltsverzeichnis.
  • Changelog und RSSEine „Was ist neu“-Seite und Feeds, erzeugt aus dem Verlauf des Repositorys.
  • Mehrere ProjekteEine Instanz liefert die Doku für jedes Werkzeug, das du pflegst.
  • Mehrere SprachenEine Seite in mehreren Sprachen unter einer Adresse, mit einem ehrlichen Hinweis, wo eine Übersetzung fehlt.
  • Eingefrorene VersionenFriere die Doku zu einem Release ein. Sie bleibt lesbar, während du weiterschreibst.
  • Entwürfe und ZeitplanungEine Seite bleibt unsichtbar, bis sie veröffentlicht wird, sofort oder zu einem festen Zeitpunkt.
  • Frag die DokuOptional Antworten nur aus deinen veröffentlichten Seiten, mit Quellen. Funktioniert mit einem lokalen Modell.
  • Backups und DiagnoseEin vollständiger Export mit einem Klick, nächtliche Backups und eine Seite, die zeigt, was eingerichtet ist.
  • Echtes HTML für SuchmaschinenTitel, Beschreibungen, Open Graph, strukturierte Daten, Sitemap und robots.txt.
  • Funktioniert auf dem HandyFür Leser und für Schreibende im Admin und im Editor.

In etwa einer Minute ausprobieren

Docker mit dem Compose-Plugin ist die einzige Voraussetzung. Jede Einstellung hat einen funktionierenden Standardwert.

Docker Compose
git clone https://github.com/Syntaxlab-dev/DocuWaves.git
cd DocuWaves && cp .env.example .env
docker compose up -d --build
# dann http://<dein-server>:8091 öffnen

Lieber nicht selbst bauen? Nimm das Image ghcr.io/syntaxlab-dev/docuwaves:stable.
